# OWASP Top 10:2025 — control, prueba y archivo

Cada categoría de la spec §13.2 apunta a un control del código, a la prueba automática que lo vigila y al archivo donde está. Si una prueba deja de pasar, el build (`./gradlew build`) falla. Lo que **no** se prueba en el backend está marcado como tal.

| Cat. | Control | Prueba que lo vigila | Dónde está |
|---|---|---|---|
| **A01 Broken Access Control** | El rol se exige en cada caso de uso (`ctx.require(...)`); el taller activo se valida contra las membresías en cada solicitud; un recurso de otro taller responde `404` | `AccessMatrixTest` (61 casos: rol × endpoint de §3.1, anónimo, taller ajeno, administrador, portal del propietario), `OwnerPortalIntegrationTest`, `CashdeskIntegrationTest.onlyTheOwnerHandlesCashAndAlerts`, `MotorcyclesIntegrationTest.customersNeverLeakAcrossWorkshops` | `WorkshopContext`, `WorkshopContextFilter`, `*UseCase` |
| **A02 Security Misconfiguration** | Encabezados `nosniff`, `X-Frame-Options: DENY`, CSP restrictiva, `Referrer-Policy`, `no-store`; Actuator solo `health`; cookie `HttpOnly` + `SameSite=Lax`; imagen *distroless* no root | `OwaspSecurityTest.securityHeadersAreOnEveryResponse`, `onlyHealthIsPublicAndManagementEndpointsAreClosed`, `theSessionCookieIsHttpOnlyAndSameSiteLax` | `SecurityConfig`, `application.properties`, `backend/Dockerfile` |
| **A03 Software Supply Chain** | Verificación de dependencias de Gradle (`verification-metadata.xml`), actions fijadas por SHA, imágenes base por *digest*, Trivy (sistema de archivos e imagen) + Grype, SBOM CycloneDX, Dependabot agrupado | CI: `dependencies`, `image` (Trivy y Grype fallan con CRÍTICAS corregibles). | **A04 Cryptographic Failures** | Argon2id; tokens, códigos de reclamación y links guardados solo como SHA-256; llaves de firma cifradas con AES-256-GCM (el taller va como dato autenticado); `SecureRandom` obligatorio; comparación en tiempo constante | `OwaspSecurityTest.passwordsAreArgon2idAndTokensAreStoredOnlyAsHashes`, `CryptoAndLimiterTest` (KeyCipher, tokens), `SecurityArchitectureTest.onlySecureRandom` | `shared/crypto`, `KeyCipher`, `ChainVerifier` (`MessageDigest.isEqual`) |

| **A09 Security Logging & Alerting Failures** | Auditoría de solo-insertar (`audit.audit_event`); logs sin PII ni secretos; una cadena `INVALID` deja un log `ERROR` con el prefijo `SECURITY` | `OwaspSecurityTest.logsNeverCarryPersonalDataSecretsOrCodes` (captura los logs de registro, login, cliente y entrega), `SecurityArchitectureTest.noStandardStreams` | `AuditService`, `HistoryApiImpl`, `ApiExceptionHandler` |

## Lo que este documento no promete

- **DAST:** el *baseline* de ZAP corre en el CI contra `/actuator/health`; no recorre la API autenticada.
- **RLS (spec §8.2):** la segunda barrera (políticas por taller en PostgreSQL) **no está implementada**; hoy el aislamiento es solo de aplicación y lo prueba `AccessMatrixTest`. Está en el plan como T8.
- **TOTP:** no implementado; ver `docs/decisiones/0011-totp-aplazado.md`.
- **Almacenamiento de las llaves:** el servidor guarda las llaves privadas; la firma da integridad, no no-repudio frente a la plataforma (ver README).
